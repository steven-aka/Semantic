# V17 experimental-chain integrity audit (2026-09-21)

Scope: read-only checks of the current train-side lineage and cached Qwen3-8B outputs, plus zero-Target-call correction of two recent pilot summaries. This audit does not validate model generalization or reopen the 581-query design-exposed gate, internal300, development, or fresh confirmation.

## Findings

1. **Confirmed Complete aggregation error in SLOT-B0 and INSERT-D0.** Both scripts used `all(hits)` on five-anchor vectors. Ten of the 24 pilot queries have no attainable 0.95 anchor, represented by `None`, which must be masked. Replaying their saved per-query records changes the baseline Complete count from **9/24 to 10/24**, fixed shortest insertion from **8/24 to 9/24**, and each oracle policy from **9/24 to 10/24**. The relative comparison and the decision to withhold a deployable Pareto claim do not change. Source code, summaries, and RESULTS/plan text are corrected; original summaries remain in `original_summary_before_complete_correction.json`.

2. **Confirmed secondary-analysis parser mismatch on a QAMPARI proper name.** Raw Target output is parsed once before storing a `#`-joined answer list. Applying the raw-output parser again to a stored answer list beginning `No. 17 Squadron` yields the boolean answer `no`. Directly parsing the saved list reproduces **every stored F1** in P0 (17,052 rows), R1 label-scale (1,485), SLOT-B0 (84), and EXEC-A1 (5,684). Double parsing would change 12, 7, 0, and 4 rows respectively, all for query `61482__wikitables_composition__train`. Thus the fresh Target scoring and recent SLOT-B0 result are not corrupted. Cached-answer consumers in the exact-cache gate and secondary analyses have been changed to a distinct cached-list parser. Older analyses using those consumers should be treated cautiously until independently replayed; this audit does not assert that their published aggregate result changed.

3. **Train-side lineage isolation checks pass.** The 581 lineage holdout, 550 inner-validation queries and 2,032 clean-train queries are disjoint. V8/V10/V12 holdout identifiers agree, and V13's train/holdout identifiers respect the same partition. P0's 1,421 queries are within clean train, R1's 512 within P0, and SLOT-B0's 24 within R1. The 17,052 P0 cached rows contain one row per query and depth 1–12. This checks identifiers and artifacts, not every historical model gradient or file access.

4. **Historical cache remains a limited provenance source.** The original exact cache and current experiments both name Qwen3-8B as Target; Qwen3-4B was the V8 representation model. The old exact cache did not record weight/tokenizer hashes, effective batch or software stack. The existing fresh-vs-historical four-mask audit found F1 changes on **788/5,684** states, including **81 old-success→fresh-failure** and **260 reverse** at 0.90. This is cross-run/contract disagreement, not proof of within-run randomness. Recent P0 uses batch size 128 while R1/SLOT-B0 use 64. Consequently old exact-cache labels must not be silently mixed with fresh-contract outcome labels or treated as an identical Target realization.

5. **Evaluation scope is narrow.** SLOT-B0 is deliberately balanced 12 successes/12 failures and design-exposed, so its rates do not estimate population performance. Candidate oracles use Target outcomes that are unavailable to deployment. `attainable_levels` and gold answers are legitimate for labels/audits, but must not enter a deployable decision feature. This audit found no evidence of such leakage in the reviewed SLOT-B0 input construction; it did not certify every older training path.

## Consequence for the next experiment

Use the corrected `None`-masked Complete semantics and the current fresh Qwen3-8B contract as the only comparable outcome source. Keep old exact-cache numbers historical and mark design-exposed train results accordingly. Before training or collecting new Target labels, freeze the next action's deployment-visible inputs, stopping schedule, Target execution manifest and paired quality–token gate. The two corrections above do not themselves provide a new deployable quality–token improvement.

Reproduce the machine checks with `python -m src.evaluation.v17pipeline_integrity_audit`. This uses Python's standard library and makes no Target calls. Parser separation and correction replay were also checked locally. Full GPU Target replay was not part of this audit.
